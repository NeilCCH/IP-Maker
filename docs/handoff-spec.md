# 個人品牌工作台｜Claude Code 開發交接

> 本文件整理本次對話中使用者已確認的 APP 需求。請以本文件為開發依據，不要把現有展示版當成完整產品。功能完成須以可操作、可驗證的結果為準。

## 1. 產品目標與使用情境

為保險業務同仁建立個人品牌與數位服務入口。團隊規模大，使用者包含新人、資深業務員，以及完全不懂社群經營、LINE OA 或網站設定的人。

產品名稱暫稱「個人品牌工作台／品牌實驗室」。不是只做 LINE OA 的工具，而是以同一份品牌核心資料，持續產出不同平台的品牌成果。

### 已確認原則

- 以業務員個人品牌與個人帳號為主體，不串接公司系統。
- 優先採用免費資源、個人 Google 工具與官方既有功能。需要付費時，先清楚說明用途、費用與替代方案，不預設訂閱。
- 採網址開啟的 PWA，可加入手機主畫面，以 APP 方式使用；手機、電腦都要好操作。
- 假設使用者完全不懂：使用者主要負責回答、選擇與確認，系統處理素材、配置與可自動完成的設定。
- 全部問項都有開放回答欄位，讓使用者快速選答，也能表達自己的需求。
- 品牌資料可重用、修改、匯入匯出，後續新增平台不必重新填整份問卷。
- 品牌視覺產出時，提供三種不同風格的介面提案供使用者看圖選擇。
- 支援為外部 AI 生成完整提示詞，讓 Claude Code、Claude、Gemini、ChatGPT 等接續處理。

## 2. 已確認的試辦背景

這些是產品使用情境，不是要放入一般使用者的品牌資料：

- 先以小組試辦，再複製到團隊。
- 新人與資深同仁混合編組。
- 第一輪四週；同仁每週可投入至少兩小時。
- 主持人加一至兩位支援夥伴；夥伴會基本 AI 操作及簡單圖文，LINE OA 仍需熟悉。
- 第一輪以基本建置完成、會操作並開始固定經營為目標，先不以成交或約訪作為驗收要求。
- 分兩層培訓：同仁學基本建置及日常管理；主持人與夥伴學進階串接、自動化，再協助同仁套用。
- 最早討論聚焦 LINE OA，但後續使用者已明確擴大 APP 範圍，五個平台都必須內建。

## 3. 五個平台都是預設產出功能

以下不是候選清單，也不是只讓使用者選其中一項開發。成果頁必須固定提供全部五個平台，每個都需要具體產出能力。使用者可以先使用一個平台，但其他成果入口應保留。

| 平台 | 預設品牌包 |
| --- | --- |
| Facebook | 頭像、封面、個人介紹、貼文版型、文案與製作提示詞 |
| 個人網頁 | 網頁版型、個人介紹、服務內容、聯絡入口、網頁製作提示詞；可供部署的實際檔案 |
| Instagram | 頭像、自介、精選動態封面、貼文與短影音封面、文案及提示詞 |
| LINE OA | 頭像、歡迎圖卡與訊息、圖文選單、入口功能、設定資料與指引 |
| Threads | 頭像、自介、文字風格、主題方向、貼文範本與提示詞 |

每個平台提供一致的操作：

**預覽 → 修改 → 下載素材 → 複製提示詞 → 設定引導**

各平台共用品牌資料，但依平台版面、文字與操作特性調整，不要把同一張圖直接塞進所有平台。尺寸、平台 API 與授權能力於實作時查核官方文件。

## 4. 初學者的主要流程

### 第一步：說說你自己

- 一次一題，提供簡單選項。
- 清楚標示單選、多選與最多選幾項。
- 每題都有常駐的「自行補充／其他想法」欄位，不必先選「其他」才顯示。
- 允許只選選項、選項加文字、或不選任何選項直接文字回答。
- 顯示進度，可返回修改，自動保存。
- 不要求使用者理解 API、JSON、圖文選單座標等術語。

### 第二步：選喜歡的樣子

- 使用同一份品牌資料，產出三種不同風格的可視提案。
- 讓使用者直接看圖比較後選定；不能只有三個名稱或色票。
- 差異應包括版面、字體層級、圖示、留白、卡片與裝飾方式，不能只換顏色。
- 每款都要遵守使用者客群、個性、照片偏好與禁忌，不可因為要湊三款而忽略明確限制。
- 選定後套用到預覽、下載素材、網頁、品牌資料與提示詞；其他提案可回頭比較。
- 修改品牌內容後可更新三款提案，保留原有答案與服務入口。
- 可提供文字修改要求，但只有實際接上並驗證文字修改能力，才可宣稱會自動理解及改圖。

### 第三步：連接並完成

- 展示要套用的內容與影響，再執行使用者授權的設定。
- 能由官方 API 或 Agent 完成的工作，由系統接手。
- 必須由使用者登入、驗證、同意條款或完成的平台動作，分成一次一個簡單步驟，附圖或直接導引。
- 最後明確顯示「已完成」「待本人操作」「尚未串接」，提供測試入口。
- 不得放一個沒有實際作用的「授權／一鍵完成」按鈕，假裝所有設定已完成。

提示詞、設定檔與進階管理仍要存在，但收進進階工具，避免干擾初學者。主入口以「開始建立我的品牌」為核心。

## 5. 個人品牌問答規格

以下可作為第一版題庫。選項可擴充，但每題都保留開放回答。

| 題目 | 預設選項或處理方式 |
| --- | --- |
| 第一印象／個人特質 | 專業可靠、親切好聊、沉穩安心、年輕有活力、細膩有溫度、思路清楚有效率；最多兩項 |
| 主要客群 | 年輕人、新婚與新手爸媽、成熟家庭、退休與準退休者、企業主與自營業者、不限定；最多兩項 |
| 服務專長 | 保單整理、退休生活與現金流、資產傳承、企業與家庭風險、醫療長照、理賠日常服務；最多兩項 |
| 配色偏好 | 多組實際色卡，每組附顏色組合與簡短風格特質，也能交由系統建議 |
| 照片使用 | 醒目呈現、適度呈現、不放照片、由系統建議；可上傳真實照片 |
| 視覺風格 | 專業科技、簡潔俐落、沉穩精緻、親切自然、交由系統搭配 |
| 文字語氣 | 專業直接、穩重親切、簡短俐落、系統建議；附短範例 |
| 服務優先順序 | 從服務清單選擇與排序，允許自訂 |
| 名稱呈現 | 姓名、姓名加定位、個人品牌名稱、系統建議 |
| 品牌名稱 | 輸入既有名稱，或提供三個提案讓使用者選擇；不得固定對所有人只給衡遠 |
| 命名方向 | 穩健安心、理性前瞻、人生從容、系統搭配 |
| 避免事項 | 過度金色、卡通、過多科技光效、文字擁擠、制式保險廣告感等；可複選 |
| LINE OA 配置 | 每頁六格或八格，單頁或雙頁，頁名、入口名稱與功能 |

### 配色要求

使用者明確要求：配色題增加選項，並說明顏色組合的特質。不能只顯示「藍色／紅色」。

可提供冷白＋電光藍＋青藍、白＋海藍、白＋紫＋青藍、白＋靛藍＋珊瑚色等方案，但應考量使用者禁忌，不硬套單一色系。

### 自由回答的處理

- 保存原文並納入品牌資料、設計規則及提示詞。
- 能解析的要求轉成可編輯設定；不能解析的，明確說明需確認或手動調整。
- 選項與文字衝突時請使用者簡單確認，不可默默丟棄任一方。
- 不把自由文字直接當成 HTML、程式或系統指令執行。

## 6. 共用品牌資料與延伸架構

品牌核心與平台配置分開管理，建議至少包含：

```text
brandProfile
  schemaVersion
  identity: 名稱、定位、標語、個人特質、客群、專長
  visual: 配色、字體規則、照片、照片偏好、禁忌
  voice: 語氣、歡迎文字
  freeform: 每一題的自由回答
  designProposals: 三款風格提案及各自規則
  selectedDesignId: 已選風格
  platforms
    facebook
    website
    instagram
    lineOA
    threads
```

- 名稱、色彩、照片、語氣變動時，各平台能沿用更新後資料。
- 平台專屬內容可自行編輯，不因共用資料變更而無聲覆寫手動內容。
- 提案切換不得刪除入口、網址、問答或其他平台資料。
- 匯入匯出須有版本標記與資料檢查，兼容舊進度。
- 未提供本人照片、資格、經歷或聯絡資料時，使用明確待填欄位；不得虛構。

## 7. LINE OA 詳細規格

### 視覺範圍

沿用 LINE 官方既有聊天框架，主要設計頭像、帳號形象、歡迎圖卡、歡迎訊息與圖文選單。不要把官方無法客製的原生框架當成能部署的自訂 UI。

### 版型

- 單頁六格：三欄乘兩行。
- 單頁八格：四欄乘兩行。
- 可開雙頁；每頁八格時，共十六個服務入口。
- 切頁按鈕獨立放在上方，不占八個服務格數；格子和切頁區都要有正確點擊範圍。
- 支援頁名、入口名稱、功能說明、文字回應或網址設定。
- 切換六／八格或單／雙頁時保留被隱藏的原有入口。
- 示意圖、可上傳的選單圖檔及點擊區設定，分別產出，不能只有手機外框合成圖。
- 官方現成範本與 API 自訂選單能力不同。八格及分頁切換的實作採 Messaging API 或有對應能力的工具；實作前查核官方規格。

### 衡遠範例：第一頁八入口

| 入口 | 預設功能 |
| --- | --- |
| 認識衡遠 | 個人介紹、專業經歷、服務理念 |
| 退休規劃 | 規劃說明、需求填寫 |
| 企業風險 | 風險檢視、諮詢需求 |
| 家庭保障 | 保障整理、需求填寫 |
| 實用資訊 | 文章分類、實用清單 |
| 預約諮詢 | 選擇時段或填寫預約；未有即時排程功能時要標明人工確認 |
| 服務協助 | 常見問題、服務申請 |
| 留言給我 | 引導聊天室留言，由本人回覆 |

第二頁入口允許自訂，展示版中的十六項範例不是強制業務需求。

### Google 與資料工具

優先考慮個人 Google 表單、試算表、日曆或 Sites，不串公司系統。

曾討論的第一個需求收集流程是：LINE OA → Google 表單 → 試算表 → 業務員處理。收件通知、處理狀態與提醒屬後續可延伸功能，尚未全部確認要在第一版實作，不要宣稱已串接。

## 8. Agent 授權與代設能力

使用者希望授權 Agent 協助完成設定，並把人工步驟壓到最少。這是待實作的重要能力，不是現有成果。

### 實作方式

- 優先使用官方 API，沒有 API 的項目再評估受控的瀏覽器協助。
- 區分 LINE 登入、OA 管理權限、Messaging API 憑證；不可把一般 LINE 登入視為已獲得 OA 管理權。
- 帳號建立、Messaging API 啟用、Provider 選擇及必要同意，依官方目前流程處理，不假設存在通用的一鍵授權。
- 可自動處理的候選工作：建立及上傳圖文選單、點擊區、分頁 alias、預設選單及連結配置，須逐項驗證。
- 歡迎訊息、關鍵字回應、個人檔案等項目要確認官方能否透過 API 管理，無法管理就提供最簡單的後台引導。
- 「設定成功」須在目標帳號實際確認；API 回傳成功不代表全部客戶端流程完成。

### 憑證與可靠性

- 不把權杖放在網頁程式碼、localStorage、下載檔或提示詞中。
- 真正代設需要安全的服務端或受控執行環境；目前靜態 PWA 不能單獨承擔此工作。
- 讓使用者知道授權範圍，可解除連接；防止不同使用者帳號的資料或憑證互用。
- 套用前列出要更動的內容，保留原設定或回復方式，避免失敗後留下半套配置。
- 能力範圍、費用及外部平台限制用簡單文字呈現，不把技術細節塞進主流程。

## 9. 提示詞生成：必要的核心產出

### 操作

1. 選擇製作用途：五個平台各有專用入口，不只泛稱「社群」。
2. 自動帶入共用品牌資料、已選風格及該平台配置。
3. 使用者可輸入本次額外要求。
4. 顯示可編輯的完整提示詞，支援複製及 TXT 下載。
5. 品牌資料或風格更新時，提示是否重新生成，避免無聲覆寫手動修改。

### 提示詞必含

- 製作任務、平台、用途與交付項目。
- 品牌名稱、定位、客群、專長、標語。
- 配色、版面、照片使用、語氣、已選風格規則。
- 每題自由回答、明確禁忌與額外要求。
- 該平台的入口、內容或版型配置。
- 台灣繁體中文，避免虛構肖像、經歷、資格與功能完成狀態。
- 免費資源優先；涉及費用先說明。
- 示意圖、可編輯素材、程式、部署與串接的完成範圍分開標示。

提示詞生成可先採規則式組合，無須為此強制付費 AI。規則式排版、AI 生圖、實際部署應明確區分。

## 10. 使用者本人「衡遠」範例資料

這是測試範例，不是所有同仁的預設人格：

- 品牌名稱：衡遠；使用者從命名提案中選定，尚未查核同名或權利。
- 個人特質：專業可靠、思路清楚有效率。
- 客群：退休與準退休族群、企業主及自營業者。
- 專長：退休生活與現金流、企業經營與家庭風險。
- 定位文字：退休規劃・企業與家庭風險。
- 標語示例：衡量當下，規劃長遠。
- 文字語氣：簡短俐落。
- 照片配置與初始配色由系統建議。
- 優先入口：認識我、企業與家庭風險、實用資訊。
- 最初選沉穩精緻，但看到具體設計後，明確改為專業科技感，後者為最新方向。
- 明確拒絕先前深藍、米白、香檳金、山景及古典字體的組合：使用者認為像台灣訃聞視覺，非常不喜歡。
- 最新接受方向：冷白、電光藍、青藍，現代無襯線字體、俐落幾何線條，適量科技層次。
- 避免卡通可愛、文字擁擠、制式保險廣告感。
- 三種風格都應尊重這些限制，不可把被拒絕的設計重新當成候選。
